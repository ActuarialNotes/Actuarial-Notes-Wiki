# Resolve: Exam FM open findings (209 files, 258 findings closed)

The follow-up to run `2026-09-28T14:47Z/aa33`, which fact-checked all 456 Exam FM files and left
258 findings open on 208 of them (2 critical, 50 major, 188 minor, 18 nit). This run fixed the
content behind every one of those findings, closed each with a logged resolution, and re-verified
each file with a new pass bound to its new bytes. It also wrote the page for the one reading the
syllabus calls required, SOA study note FM-24-17. Nothing in the Exam FM scope is left with an open
finding.

  of the August 2026 PDFs. An explanation with drafting text, a wrong intermediate chain or a method

  displayed number recomputed in python. Where SOA's own solution has a slip, the correct value is
  used and the resolution says so.
- **Concept pages** were corrected to what a cited source says. A claim no source supports was
  deleted. A wrong worked example was recomputed in full. Empty placeholder pages were written.
- **Tags** follow the syllabus outcomes and `scripts/ontology_map.py`.
- **Cross-exam conflicts** were fixed on the CAS side: the CAS questions that linked an FM-sense page
  were retagged to the page for the sense they mean.

## Process

and resource pages. They shared one written policy and a lookup tool keyed by SOA question number
(text and page images). Roughly 4.5M tokens in all, about 230k per batch.

- **Checkpoint commits.** WIP checkpoint commits were pushed while agents worked. The verify-check
  workflow's sync commits on those pushes recorded derived fields for half-edited files, so they
  were merged with their content set aside. The final record was re-checked from scratch.
- **Usage limit.** A usage limit stopped the resource agent after it had recorded every file but
  before it reported. Its work was reviewed against the logs and the diff.
- **Double passes.** A few files (fm-098, fm-151, fm-226, fm-319) carry two passes, the second
  after a lint fix, each noting why.
