## The decision tree

The whole reading turns on section 4. For a material event learned of after the calculation date but before the report date, the actuary asks:

1. **Does the event provide information about an entity's circumstances that existed at the calculation date?**
   - **Yes** — the event is *evidence about a condition that already existed*. **Take it into account** in the valuation. A court decision on a claim already incurred, a large claim reported late, an adverse development that reveals the estimate was wrong: these change the number.
   - **No** — the event *creates a new condition after the calculation date*. **Do not take it into account** in the valuation, but consider whether it must be **disclosed**.
2. For an event that makes the entity a **different entity** (a sale, a wind-up, a merger, a portfolio transfer), the actuary values the entity as it is *after* the event where the work's purpose requires it — the special case that breaks the simple rule.
3. **Disclosure** (§5) — a subsequent event that is not taken into account, but that a user would need to know about to understand the report, is disclosed.

## Why it is examinable

It is a rule that produces a definite answer from a fact pattern, which makes it ideal exam material: a list of events, and for each, take into account / disclose only / neither. The traps are the events that look new but are evidence of an existing condition (a judicial decision interpreting a benefit already in force), and the events that look like evidence but are genuinely new (a catastrophe after year-end).

Section 7 matters too: the actuary, management and the **[[External Auditor|external auditor]]** may each learn of an event first, and each has a different reporting obligation and a different cut-off date. That connects to [[OSFI Memorandum]] and to the actuary–auditor relationship in Domain C5.
